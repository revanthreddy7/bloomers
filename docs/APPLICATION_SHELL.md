# Application shell and data contracts

## Parent navigation and student context

`/parent` retains the authorized student cards and existing add/profile flow, and shows the first authorized student's overview. The sidebar's **Selected student** control navigates to `/parent/learners/[id]/[view]`. Views are Overview, Course, Progress, Homework and Schedule; Settings stays at `/parent/settings`. Switching preserves the learning view when possible, otherwise opens Overview. URL context survives refresh and back/forward navigation. Authorization is server-owned, independent of the selector.

Existing `/parent/students/[id]` profiles and consent decisions, enrollment forms, `/parent/students/[id]/courses/[enrollmentId]` roadmap details, and the `/curriculum` explorer remain available. Desktop uses a sidebar; mobile uses compact navigation. Shared styles retain the Bloomers palette, focus indicators and touch targets. Loading/errors and truthful empty states remain explicit.

## What the views mean

| View                    | Persisted backing                                                                                                         | Meaning and inactive capabilities                                                                                                                                                                                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview / preview Home | Profile, enrollment, exact publication, plan, reservations, lesson metadata, skill/evidence references, homework metadata | Shows active/completed enrollment, next planned objectives, upcoming dates, estimated completion, recent recorded attendance and honest progress/homework state. No AI insight or attention diagnosis is generated.                                                                                                                   |
| Course                  | Pinned publication hierarchy, plan items, canonical reservations                                                          | Separates academic requirements from ordered student-specific estimated work and actual calendar reservations. Future lessons remain Planned. Existing detailed roadmap links remain stable in parent mode.                                                                                                                           |
| Progress                | Pinned skill definitions, canonical skill state and matching last evidence references                                     | Displays Not yet assessed unless an evidenced state has positive count and a matching student/skill evidence reference. Evidence recorded is not Mastered. The score does not prove the publication's independent-correct/hint requirements; Phase 7 must supply reviewed classifications. No percentages or synthetic charts appear. |
| Homework                | Student assignments, scoped submissions, existence of review results                                                      | Assigned/Submitted/Reviewed require corresponding persisted metadata. In-progress tracking is unavailable. No private questions, answer keys or grading payloads are retrieved. No assignment or submission is created. Partial reads do not assert Assigned when submission absence is unknown.                                      |
| Schedule                | Canonical `lesson_schedules` start/end/status/timezone and associated plan objectives                                     | Monday–Sunday weeks in the first loaded course's selected timezone, or explicitly labeled UTC if no initialized course exists. Previous/current/next week navigation, elapsed duration and upcoming reservations. No join/edit/recalculate control.                                                                                   |
| Settings                | Existing verified parent identity and profile-specific consent UI                                                         | Parent-only. Preview cannot load it; capability grants/activation remain governed by existing draft policies.                                                                                                                                                                                                                         |

Reservation completion/missed statuses are displayed as recorded schedule states, not inferred attendance or mastery. Attendance counts come from the latest actual `lessons` metadata; a completed session requires recorded start and end. Every date and course completion projection is labeled as an estimate. Initial planners/reservations remain unchanged if a new curriculum is published.

## Read-service contracts and limits

`server/application/service.ts` provides `listApplicationStudents` and `getLearningView(studentId, mode, week)`. `features/application/models.ts` contains pure academic/progress/homework/attendance/timezone/week view models. `LearningViewModel` is a server-side aggregate; presentation consumes it without client-side database authorization. Preview client navigation receives only the selected student ID. Parent navigation receives a bounded authorized display-name/ID list, never session details.

Direct reads filter the authorized student ID. Roadmaps reuse the Phase 3 service, which checks student/enrollment pairing and published pins. Progress evidence lookups request only IDs and skill IDs for existing evidence references in batches of at most 1,000. No raw payload, private answer, transcript, report or AI run is fetched. Homework joins are bounded to selected assignments and submissions.

Limits are 50 selector profiles, 10 loaded enrollments, 50 assignments, 200 recent submissions, 50 recent lesson records, 100 week reservations and 10 upcoming reservations. Extra rows set a visible partial-view notice. Current week retrieval pads local date bounds by one UTC day and filters exact local week membership; this handles offsets, DST and date boundaries without inventing new calendar state. Week navigation is limited to ±104 weeks. Weekly and upcoming queries include canonical reservations without a course-plan link; associated objectives appear only when resolved from an authorized loaded plan.

## Student preview and future access

Enter through **Open student preview** in the selected student's parent learning view. Routes `/preview/[id]` and `/preview/[id]/course|homework|progress` provide the four student navigation destinations; `/preview/[id]/schedule` is available from Home's weekly schedule. A persistent banner identifies the session as a parent-assisted preview. It has no sibling selector, account email, settings, consent management or privileged learning controls.

The private database scope binds the parent Auth session to one student. RLS narrows reads; parent identity/enrollment/consent mutations reject active previews even through direct RPC. A sibling/foreign preview URL returns 404. Parent/account/auth GET navigation redirects to the selected preview. Account-changing application actions fail closed while preview is active. Removing a UI marker cannot restore broader access because there is no scope cookie to trust.

Choose **Return to parent mode**, then **I’m the parent — continue**. This explicit confirmation ends the scope and returns to the same parent's student overview, where switching becomes available again. Keep the guardian present: this is supervised viewing, not an authenticated guardian-return challenge or an unattended device handoff. The browser retains parent Auth credentials; this does not restrict Auth's own APIs or turn the account into a child credential. Close other parent tabs before preview. See [ADR 0009](architecture/0009-application-shell-and-student-preview.md) for the boundary and approval requirements for a future secure handoff/student authentication design.

No lesson room, voice, camera, upload, avatar, LLM, diagnostics, mastery engine, homework workflow, notification, analytics or adaptive recalculation is activated. Phase 5 remains unstarted.
